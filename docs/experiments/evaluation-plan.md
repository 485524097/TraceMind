# 检索与 RAG 评测计划

## 目的

以可复现数据衡量检索和回答质量，为 Chunking、检索、重排和模型策略提供决策依据。

## 评测集

- 来源：仅使用有授权、可公开或可本地留存的技术文档与代码样本。
- 单条样本：问题、目标知识库、期望证据 Chunk/文档、期望答案要点、问题类型。
- 类型：精确定位、跨文档关联、代码行定位、PDF 页码、资料不足、中文自然语言表达。
- 划分：固定开发集用于调参，保留测试集只用于比较最终方案；两者均需版本化。

## 指标

| 环节 | 指标 | 说明 |
| --- | --- | --- |
| 召回 | Recall@k、MRR、nDCG | 目标证据是否在候选结果中且排序合理。 |
| 重排 | nDCG@k、MRR 变化 | 与召回基线比较收益。 |
| 回答 | 正确性、完整性、资料不足拒答率 | 人工标注或明确 rubric 评分。 |
| 引用 | 引用正确率、引用覆盖率、定位精度 | 引用是否真实支持回答且页码/行号准确。 |
| 工程 | P50/P95 延迟、失败率、单问成本 | 评估可用性和运行成本。 |

## 实验流程

1. 固定评测集、索引版本、模型版本和配置。
2. 记录当前基线结果。
3. 每次只改变一个主要变量，运行相同评测。
4. 记录指标变化、失败案例、成本和延迟。
5. 只有在质量提升且风险可接受时，才将实验配置升级为默认方案；否则保留基线或回滚。
