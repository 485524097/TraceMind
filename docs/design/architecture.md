# 架构设计决策

## 当前架构边界

TraceMind 采用 FastAPI 后端、Vue 3 前端、PostgreSQL 元数据存储、本地原文件存储、Redis/Celery 异步任务和 Qdrant 向量索引的分层架构。

- API：HTTP 协议、请求校验、响应和错误映射。
- Service：用例编排、事务边界、跨资源补偿与业务规则。
- Repository：数据库查询和持久化，不提交事务。
- Storage：本地文件安全写入、校验、原子移动和可恢复删除。
- Parsing：确定性解析与 Chunking，不依赖 HTTP、数据库或消息队列。
- Integration：封装 Redis、Qdrant、模型 Provider 等外部依赖。

## 已知演进原则

- 索引与原文解析结果分离：`DocumentChunk` 是可追溯事实源，检索索引是可重建派生数据。
- 任何异步流程必须具备幂等性、状态可见性和失败后的重试/恢复路径。
- 业务代码不直接依赖具体模型或向量数据库 SDK，统一经 Integration/Provider 边界访问。
