# RAG 设计

## 目标

根据用户问题，从指定知识库中找到可验证资料，生成中文回答并返回精确、可打开的来源引用。

## 目标链路

```text
用户问题 → 查询规范化 → 全文召回 + 向量召回 → 融合 → Reranker
→ 上下文组装 → 模型回答 → 引用校验与输出
```

## 不可违反的约束

- 引用仅由被选中的 `DocumentChunk` 元数据生成，包含文档、版本、页码、章节或代码行号。
- 文档版本更新、重新解析或删除后，索引必须幂等地同步；旧版本不得混入默认检索结果。
- 没有充分上下文时，回答必须声明资料不足，并给出可检索到的范围。
- 解析成功不等于索引完成；后续须区分解析、索引和可检索状态。

## 后续决策记录

每次改变 Chunk 参数、Embedding、全文检索、融合算法、Reranker、上下文组装或提示词时，补充：

- 问题与假设；
- 数据集与基线；
- 候选方案及未选原因；
- 指标、结果、延迟和成本；
- 灰度/回滚方式。
