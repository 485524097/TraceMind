# 星澜浮岛能源编排系统技术手册

本文件是完全虚构的检索评测语料，不描述任何真实系统。

星澜浮岛能源编排系统服务于虚构的“澄空群岛”，负责在漂浮居住舱、藻光农圃和气象桅杆之间编排能源。手册中的组织、模块、协议、配置、错误码与运行数据均为虚构内容，只用于验证中文技术资料的检索稳定性。系统把能量采集、需求预测、配额计算、输送调度、储能调节和审计追踪拆成相近但互不替代的职责，运维人员必须依据章节中的边界处理事件。

## 1. 系统边界与运行周期

系统以十五秒为一个“潮拍”，每四个潮拍形成一分钟调度窗。晨潮采集器在潮拍末尾封存观测值，霁光预测器在下一潮拍开始时计算未来十二个调度窗的需求，脉轮协调器随后生成配额草案。雾桥路由器只负责把已批准配额转换为输送路径，不参与需求预测。余辉储能器根据路径余量决定充放电动作，银弦审计器最后记录每次决策的来源。

调度窗并不等于结算窗。调度窗用于实时输送，默认一分钟；结算窗用于汇总责任与损耗，默认三十分钟。把二者混用会让短时削峰被误认为长期欠供，但不会改变现场控制器已经执行的路径。

## 2. 晨潮采集器

晨潮采集器接收浮岛边缘的风帆阵列、热翼板和重力摆的观测包。它校验观测时间、设备序列和单位，将同一潮拍的重复包合并为一个不可变快照。配置项 `tide.collect.window-seconds` 控制潮拍长度，默认值为 15；`tide.collect.late-grace-seconds` 控制迟到包宽限，默认值为 6。

采集器只保证输入快照完整，不判断未来需求，也不向输送节点下达动作。迟到包在宽限期内会重开当前快照，超过宽限期则写入旁路记录，并产生错误码 `SLR-COL-104`，含义是“观测包超过潮拍宽限”。该错误不会触发全岛停供。

静默也是一种观测。

## 3. 霁光预测器

霁光预测器读取最近二十四个调度窗的快照，并结合虚构节律表推算未来十二个窗口。配置项 `dawn.forecast.horizon-windows` 决定预测跨度，默认 12；`dawn.forecast.min-samples` 指定最少历史窗口数，默认 8。历史不足时，预测器返回保守曲线并标记低可信来源。

预测器输出的是需求区间和峰值时刻，不产生岛屿配额。若输入快照的单位无法统一，它拒绝该序列并返回 `SLR-FOR-207`，表示“预测输入单位不兼容”。相似的 `SLR-FOR-208` 表示历史样本不足，两者都来自预测阶段，但前者需要修正单位，后者通常等待更多快照即可恢复。

## 4. 脉轮协调器

脉轮协调器把需求区间、岛屿优先级和维护约束组合成配额草案。它先保障生命维持舱，再处理农圃与工坊；同级对象按照上个结算窗的欠供比例轮转。配置项 `pulse.quota.reserve-percent` 表示预留比例，默认 9，合法范围为 0 到 30。

配额草案必须经过规则校验才会成为已批准配额。若预留比例超出范围，协调器返回 `SLR-QUO-311`；若所有候选对象都处于维护冻结，则返回 `SLR-QUO-318`。协调器不计算物理输送路线，因此“获得配额”不代表某条雾桥必然可用。

公平不是平均分配。

## 5. 雾桥路由器

雾桥路由器接收已批准配额、桥段容量和禁行清单，计算从能量源到目标舱的有向路径。它优先选择跳数少且热损耗低的桥段；当主路径的剩余容量低于配额时，可拆分到两条互不共享脆弱节点的路径。配置项 `mist.route.max-hops` 默认 7，限制单条路径的最大桥段数。

路由器不修改配额数值，也不决定储能池是否放电。找不到满足最大跳数的路径时返回 `SLR-RTE-423`，含义是“输送路径不可达”；存在路径但总容量不足时返回 `SLR-RTE-429`，含义是“桥段容量不足”。前者应检查拓扑与禁行清单，后者应调整配额或请求储能支援。

路径短不代表余量大。

## 6. 余辉储能器

余辉储能器管理虚构的星砂电芯池。它根据已批准路径的缺口、当前荷电比例和未来预测峰值生成充放电计划。配置项 `afterglow.storage.floor-percent` 默认 22，表示常规调度不得突破的最低荷电比例；紧急生命维持事件可由双人授权临时越过该下限。

当荷电比例低于下限且没有紧急授权时，储能器拒绝放电并返回 `SLR-STO-512`。当电芯温差超过虚构安全阈值时返回 `SLR-STO-519`，同时冻结充放电，但不会撤销脉轮协调器已经批准的配额。储能计划和配额计划名称相近，前者描述电芯动作，后者描述对象可获得的上限。

低电量不等于零容量。

## 7. 银弦审计器

银弦审计器为快照、预测、配额、路径和储能动作生成关联记录。每条记录保存决策类型、来源版本、输入摘要、执行时间和前一条记录的摘要链。配置项 `silver.audit.retention-days` 默认 45，只影响本地审计记录保留期，不影响原始观测快照的保留策略。

审计器只证明系统当时使用了哪些输入与规则，不替代监控告警，也不会回滚现场动作。摘要链断裂时产生 `SLR-AUD-604`，该错误要求暂停归档导出并重建受影响区段；单条记录字段缺失则产生 `SLR-AUD-607`，可从对应决策对象补录。

## 8. 模块相似概念辨析

“采集快照”与“审计快照”都包含时间和摘要，但采集快照保存设备观测，审计快照保存决策来源。“配额草案”与“储能计划”都带有能量数值，但配额草案约束目标对象，储能计划约束电芯动作。“路由冻结”与“维护冻结”都会阻止执行，前者针对桥段，后者针对候选对象。

“迟到宽限”与“预测跨度”都使用时间窗口表达。迟到宽限只决定观测包能否进入当前快照；预测跨度决定输出覆盖多少个未来调度窗。二者不能通过同一个配置项调整。

## 9. 基础配置示例

以下 YAML 展示单节点实验环境的公开配置。所有名称和数值均为虚构示例：

```yaml
tide:
  collect:
    window-seconds: 15
    late-grace-seconds: 6
dawn:
  forecast:
    horizon-windows: 12
    min-samples: 8
pulse:
  quota:
    reserve-percent: 9
mist:
  route:
    max-hops: 7
afterglow:
  storage:
    floor-percent: 22
silver:
  audit:
    retention-days: 45
```

启动时配置加载器先读取内置默认值，再读取本地配置文件。未知键会被拒绝而不是静默忽略，数值越界则在任何模块启动前统一报告。

## 10. 配额生成与批准流程

协调器收到预测结果后创建 `draft_revision`，按照优先级和欠供轮转规则分配可用总量，再扣除预留比例。规则校验确认数值非负、总和不超过输入能力且维护对象未获配额。批准动作生成新的 `approved_revision`，并把草案摘要交给银弦审计器。

```json
{
  "draft_revision": "quota-draft-17",
  "reserve_percent": 9,
  "targets": [
    {"name": "虚构生命舱甲", "share": 48},
    {"name": "虚构藻光圃乙", "share": 27}
  ]
}
```

若要完整解释某个目标最终为何获得特定配额，必须同时查看霁光预测器给出的需求区间和本节的优先级、欠供轮转及预留规则；只看任一章节都无法还原完整原因。

## 11. 路径计算与容量处理

路径计算分为拓扑筛选、容量筛选和损耗排序。拓扑筛选移除维护禁行桥段；容量筛选检查候选路径能否承载批准配额；损耗排序在可行路径中选择预计热损耗较低者。拆分路径最多为两条，且不能共享标记为单点脆弱的中继。

```text
starlane route plan --quota quota-approved-17 --max-hops 7
starlane route inspect --plan route-plan-42 --show-capacity
```

处理 `SLR-RTE-423` 时先核对桥段是否被拓扑筛选移除，再检查 `mist.route.max-hops`。处理 `SLR-RTE-429` 时应查看剩余容量和批准配额，增加最大跳数不一定能解决容量不足。

## 12. 储能支援与下限保护

当路径容量不足但存在可用电芯池时，余辉储能器可以在目标附近提供支援。它先读取霁光预测器的未来峰值，再确保放电后荷电比例不低于 `afterglow.storage.floor-percent`。因此一次支援是否允许，需要联合未来需求和储能下限两处信息判断。

```python
def may_release(current_percent, requested_percent, floor_percent):
    projected = current_percent - requested_percent
    return projected >= floor_percent
```

紧急授权只绕过荷电下限，不绕过温差冻结。出现 `SLR-STO-519` 时，即使生命维持舱具有最高优先级，也必须等待电芯温差恢复到虚构安全区间。

## 13. 事件恢复顺序

单模块错误按“冻结受影响动作、保留已批准对象、记录审计、尝试局部恢复”的顺序处理。采集迟到不会停止旧快照供预测使用；预测样本不足会生成保守曲线；路径不可达只冻结对应目标的输送计划；储能温差异常只冻结电芯动作。

```json
{
  "event": "SLR-RTE-423",
  "scope": "虚构浮岛丁",
  "action": "freeze-route-only",
  "preserve": ["approved-quota", "forecast-revision"]
}
```

如果路径不可达且目标附近储能也低于下限，应保留已批准配额作为审计事实，先修复拓扑或解除禁行；储能器在没有紧急授权时不能用低于下限的电量掩盖路由故障。

## 14. 审计留存与导出

审计记录按照 `silver.audit.retention-days` 保留，过期后先生成封存清单，再删除本地明细。导出包包含摘要链起点、终点、记录数量和规则版本，不包含设备原始观测全文。采集快照由独立策略保留，因此延长审计天数不会自动延长观测数据寿命。

发生 `SLR-AUD-604` 时，导出任务必须停止在断裂点之前。运维人员从最近一次可信封存清单恢复链起点，再按决策时间重放摘要；恢复期间现场调度继续运行，但新的导出包标记为暂缓。

## 15. 观测包迟到处理

迟到不超过 `tide.collect.late-grace-seconds` 的观测包可以重开当前潮拍快照，快照版本号递增，预测器下次读取最新版本。超过宽限的包只进入旁路记录并产生 `SLR-COL-104`，不会回写已经完成的预测和配额。

若迟到包同时缺少单位，采集器先按迟到规则决定是否进入快照；只有进入快照的包才继续单位校验。旁路记录保留原始单位声明，供后续人工分析，但不能参与自动预测。

## 16. 预测退化与恢复

当历史窗口少于 `dawn.forecast.min-samples` 时，霁光预测器使用最近可用中位需求生成保守曲线，并附带 `SLR-FOR-208`。历史数量恢复后，下一次潮拍会自动回到常规预测，不需要重启模块。

单位不兼容的 `SLR-FOR-207` 不会因等待而恢复。运维人员必须修正观测单位映射，再重放受影响的采集快照。重放只生成新的预测版本，不会直接覆盖已经批准的历史配额。

## 17. 运维检查顺序

当用户报告“目标未收到足够能量”时，先在脉轮协调器确认是否获得已批准配额，再到雾桥路由器确认是否存在可行路径，最后查看余辉储能器是否因下限或温差冻结拒绝支援。跳过配额检查直接调整路由，可能为一个本就未获配额的目标制造无效路径。

当用户报告“预测突然降低”时，先检查晨潮快照是否完整，再辨别 `SLR-FOR-207` 与 `SLR-FOR-208`。前者修正单位映射，后者补足历史样本；不要因为两者都以 `SLR-FOR` 开头而采用同一恢复操作。

## 18. 安全变更窗口

配置变更在结算窗边界提交，但不同模块的生效点不同。采集窗口和迟到宽限在下一个潮拍生效；预测跨度在下一次预测任务生效；预留比例在下一份配额草案生效；最大跳数在下一次路径计算生效；储能下限需要等待当前充放电动作结束。

同时修改预测跨度与预留比例时，应先保留旧预测版本完成当前配额批准，再让新跨度生成下一版本需求，最后应用新的预留比例。这样审计器能明确区分变化来自需求范围还是分配规则。

## 19. 最小巡检清单

每个结算窗至少核对一次采集快照连续性、预测来源标记、已批准配额总和、路径冻结数量、储能下限越界次数和审计摘要链状态。巡检结果只记录状态与版本，不复制观测正文。

发现异常时应记录模块、错误码、影响对象和首次出现的潮拍编号。错误码相同但对象不同的事件必须分别保留，避免局部恢复误关闭其他浮岛的事件。

## 20. 术语与责任边界

潮拍是观测封存节奏，调度窗是实时输送周期，结算窗是责任汇总周期。快照属于采集事实，预测属于未来估计，配额属于分配上限，路径属于物理输送方案，储能计划属于电芯动作，审计记录属于决策追踪。

任何模块都不得越权修改上游事实：路由器不能提高配额，储能器不能改写预测，审计器不能替现场控制器执行回滚。跨模块故障处理应保留各自版本，通过关联标识串联，而不是把多个阶段压缩成一条不可追踪记录。
